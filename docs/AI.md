# Consultant architecture

## V2 Concierge implementation

Stage 3 adds `/concierge` and `/api/v1/concierge` alongside the compatible legacy flow described below. `src/lib/concierge.ts` defines strict per-market Briefs, grounded facts/sources, React component descriptors, UI actions and proposal-only writes. The provider interface receives prior authorized entities and tool results for up to three bounded planning rounds. The OpenAI-compatible adapter uses the installed Vercel AI SDK; without a key the deterministic bilingual parser uses the same tools.

SDK UI data streams report actual interpretation/retrieval progress and completed tool components. Trusted application copy supplies prose; raw model text is discarded. One persistent map consumes live action IDs and Brief revisions. History restoration re-authorizes references and cannot replay actions. Cancellation propagates to provider work and prevents observed in-flight persistence from committing. Explicit write confirmations are atomic and idempotent.

Parser evals and execution safety evals are separate: semantic extraction does not prove authorized retrieval or fact grounding. Current mock coverage includes105 parser cases/124 phrases and444 authorized execution cases/632 turns with13 zero safety counters. Real-provider checks remain explicitly skipped without a key. The sixth simulated board passes9.005952381/min8; final current-source hosted acceptance is pending. See the [delivery ledger](studio/DELIVERY-LEDGER.md) and [review evidence](reviews/stage-3/v6/creative-director.md).

Payment timelines retain a freshly authorized bilingual subject identity; history refreshes names and removes revoked records. Deadline interpretation notices retain their full original text in SSE and history. Optional server-generated typed context identifies the market, country, year and scope. The client may compact only an exact repeat in adjacent completed turns; it never scans past failure, cancellation, removal or missing legacy context, and never compacts unknown payment facts. The same interpretation remains beside the editable Brief deadline. Provider plans and tool arguments cannot author this presentation metadata.

## Legacy Consultant compatibility

`AIProvider` proposes allowlisted client tool calls; it never has database credentials or admin tools. The deterministic MockProvider extracts Arabic/English briefs, normalizes Arabic numerals and carries preferences between turns. `AI_PROVIDER=openai` plus a key enables the optional OpenAI-compatible Chat Completions adapter. Without a key it falls back to MockProvider. The adapter follows [official function-calling documentation](https://developers.openai.com/api/docs/guides/function-calling), requires tools and validates every argument with Zod.

The application executes tools with a freshly loaded authenticated user. All listing access passes through the shared visibility predicate. Tool facts are rendered as scoped cards and estimate panels; free-form model prose is discarded. Trusted bilingual templates explain results, no-matches and advice handoffs. This conservative MVP trades conversational variety for auditable grounding. Model-invented IDs cannot resolve to cards. A second code gate checks explicit user intent before shortlist/viewing writes.

History stores property IDs, not snapshots of restricted inventory. Every replay rechecks visibility so a revoked grant does not leak historical property details. User-entered messages are rendered as escaped text. Conversation deletion cascades to its messages. Briefs are independently editable and retained until account deletion.

The endpoint streams NDJSON status, brief, text, properties, results and done/error events. It does not stream unvalidated model tokens. The UI consumes incremental text and rich cards. Client tools cover search, scoped detail, comparison, synthetic area insights, deterministic investment estimates, saving, viewings and human handoff.

Run `pnpm eval` for the bilingual fixture suite. The same cases run on the real provider if a key is present; otherwise a clear skip is printed. No real-provider success is claimed without execution. Mock embeddings use normalized deterministic 64-dimensional hashing. With the real provider enabled, the seed re-indexes through the configured embeddings model using 64 dimensions. The embedding source is stored per property; vectors are replaced transactionally after generation, and mismatched sources fall back to full-text ranking until re-indexed. Restart through `pnpm dev` or rerun `pnpm db:seed` when changing providers.
