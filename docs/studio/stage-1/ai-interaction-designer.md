# Stage 1 · AI Interaction Designer

Start with Sheikha: a short Arabic request should receive a precise, inspectable response rather than a long chatbot monologue. The design system defines this response language before Stage 3 connects the agent.

The composer is the entry point. Submission updates an explicitly demonstrated response, not a fake live model. Voice exposes capability and permission status honestly; unsupported browser speech is explained. The Brief uses editable labelled fields, never invisible inferred constraints. A recommendation displays a reason and a trade-off. Comparison and payment timelines are independently usable evidence components.

The guide demonstrates the relationship between actions: edit a Brief field, change a layer, choose a card density, open a sheet, summon a command palette and recover from an error. Dialogs preserve context and return focus. The mobile sheet supports drag with equivalent expand/collapse controls; keyboard operation is not secondary.

Reference facts and synthetic examples cannot visually blur. Every demo card has a persistent Demo badge. Source chips carry a date and external link; trust badges distinguish developer, press report, recent listing and demo. Price components display original currency with direction isolation. No generated prose may imply stock, yields or travel times unavailable in evidence.

Arabic copy is authored for this guide, not mechanically mirrored English. It uses upright Amiri editorial typography and IBM Plex Sans Arabic UI. Persona language quality remains a review exercise, not a native-reader certification. Production voice transcription, streaming tools, map effects and memory are later-stage contracts; the living guide does not claim them implemented.
