# Stage 1 · AI Engineer

Start with Rajiv: the evidence structure must survive rendering without losing units, source dates or calculation assumptions. Stage 1 therefore defines component data contracts that a later tool can populate deterministically.

Project cards accept an identifier, name, location, evidence basis, optional explicitly typed monetary amount, recommendation reasons and trade-off. Price takes amount and ISO currency; it formats without converting. Payment milestones carry percentages, labels and timing; a total must equal100% before projection is presented as complete. Source chips accept an original HTTPS URL and supplied as-of date. Demo fixtures remain separate from reference records and never inherit real developer availability.

The living guide demonstrates UI state only. Its composer must identify its local simulated response. It does not call a real provider, persist conversation state, create a viewing or change inventory. Later Stage 3 maps allowlisted tool-result types to these components; entity authorization remains in the shared server data-access layer. UI component reuse cannot bypass that boundary.

Typing/brief edits and errors are useful contract tests: render only supplied values, preserve source labels, display missing evidence, and avoid guessed currencies or source freshness. Browser speech capability is explained rather than represented as live transcription. Structured source and price props must remain serializable between server and client components.

Acceptance evidence includes TypeScript, bilingual rendering, keyboard dialog flows and source/amount preservation. Existing API safety evals remain separate from this new UI library; no claim is made that the full v2 agent or60-case suite exists as a result of these components.
