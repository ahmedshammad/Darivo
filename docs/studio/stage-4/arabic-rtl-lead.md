## Layout and numerals

Use logical inline spacing, source-order headings and right-aligned Arabic body copy. Mirror navigation direction where meaningful, not charts, numerals, chronology or geographic maps mechanically. Keep board ordering consistent with its DOM reading order; selected comparison entries must retain identity when locale changes. Avoid letterspacing Arabic, truncating a project name into an ambiguous unit identity, or placing the essential qualification only in a tooltip.

Apply the persisted Arabic-Indic preference to amounts, dates, counts and percentages without changing raw data. Isolate currency/amount pairs, IDs, source URLs and mixed proper names with bidi boundaries. Original AED/EGP values stay visible beside optional USD/GBP conversions. A price from a reference report must not look like an exact available-unit quote. “As of,” retrieved date, generated date and last verification need distinct labels; preserve unknown/date precision instead of creating a full calendar date from a year.

## Calendar and document

Use localized city labels «دبي»، «القاهرة»، «لندن» with an explicit zone in the confirmation. Store UTC instant plus IANA zone; do not hardcode offsets because Cairo/London change seasonally. Distinguish a requested local time from its cross-city equivalents. Reject or explicitly resolve nonexistent/ambiguous civil times rather than silently shifting them. Show both date and time when conversion crosses midnight. Calendar week order follows the chosen locale consistently; month/week controls and the agenda remain keyboard usable.

The dossier contains both scripts with the preferred language first. Embed provided fonts, retain searchable/selectable Arabic text and proper bidi ordering. Use separate language blocks rather than squeezing long parallel paragraphs into fixed-height clipping boxes. Keep source references, native amounts, on-request status and Demo badges together with the relevant entry. Test long Arabic names, mixed identifiers, Arabic-Indic digits, four-entry comparisons and multi-page source appendices by rendering every PDF page. A good-looking PDF is not proof of tagged-PDF accessibility.
