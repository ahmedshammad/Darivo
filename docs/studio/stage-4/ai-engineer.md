# Stage 4 — AI Engineer

Discovery brief only; no Stage 4 implementation or schema changes. The target is a client moving from a grounded Concierge response through map and Story to a named portfolio, bilingual dossier and an explicitly requested viewing. Stage 3's accepted safety boundary remains the starting point, not permission for the model to execute writes.

Read: Master Brief V2 Parts B/H/I; current Concierge contract, grounding/replay, atomic confirmations, property visibility DAL, reference/Atlas reads, workflows, advisor inbox, PDF and schema. Installed Next data-security and route-handler guidance supports a server-only, minimal authorized DTO boundary.

The shared contract proposal is [BACKEND-PROPOSAL.md](BACKEND-PROPOSAL.md). Preserve reference-project, demo-project grouping and fictional-unit identities. A model may name authorized entity IDs, never supply canonical names, prices, source facts, action capabilities, advisor identity or access grants. Fresh resolution supplies those fields. Portfolio targets are reference projects or fictional units; a demo grouping requires selecting a visible unit. Real-project viewing language must become an explicit enquiry, not an invented appointment or residence.

Reuse the existing serializable proposal claim/write transaction. Extend it only after the direct workflow service exists; direct UI and AI confirmations call that same service. Read current role, grant, ownership, privacy and target kind at confirmation time. Idempotent confirmation must not allow a changed payload, double booking or a save after access revocation. Persist identifiers and reviewed client intent, not model-authored evidence snapshots as an authority.

The important continuity is subject identity: SouthMED stays SouthMED after a unit schedule, and a mixed dossier never turns source-level project prices into unit offers. Existing deadline contexts, native currency/payment intent, source dates and explicit unknowns survive handoff. Do not automatically copy any Brief/history to an advisor; only the exact visible client-submitted text/context is eligible. Assignment grants no additional inventory visibility. Direct office APIs enforce the same applicable doNotSave/doNotShare/doNotBook policy as AI confirmation and link to explicit settings changes rather than silently overriding them.

Acceptance tests must exercise UI, API and AI with the same private sentinel records. Cover stale verified/staff roles, revoked grants, partner accounts, replay after revocation, cross-client portfolio IDs, target-kind confusion and transaction races. Test reference enquiries and unit viewings as different effects. Preserve all 13 execution safety counters, add new mixed-target and confirmation scenarios, and record the real bilingual under-three-minute client journey. A mocked provider is acceptable for the demo; no test of it certifies live-model behavior or operational human response.

The design criterion is a shorter reliable handoff, not additional tool volume. Work is ready to begin only after shared DTOs, route identity and additive migrations are coordinated with frontend and parent ownership. No browser, DB or build was run for this brief.
