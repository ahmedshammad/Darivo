# Project Story — design proposal

Discovery only. Stage 3 is accepted; this document proposes Stage 4 implementation after the shared contract is approved. No route, schema, renderer, browser, database or build was changed for this work.

## Direction: a place, then a considered decision

`/[locale]/p/[slug]` should feel like opening a private-office research folio on a place. Use a geographic cover, generous editorial type, a persistent sense of the chosen subject and one clear next action. Avoid a photo carousel, statistic-card grid, invented architectural rendering or a brochure of unqualified adjectives.

The accepted direction is grounded in [Noir Atlas selection](../stage-0/concept-selection.md), the [Arabic Sand arrival](../../reviews/stage-2/media/v9/arrival-ar-light-390-viewport.png), [Arabic reference decision](../../reviews/stage-3/media/v7/sheikha-refined-ar-light-390.png), [named timeline](../../reviews/stage-3/media/v8-timeline-final/timeline-en-dark-1440.png) and [scoped deadline reading](../../reviews/stage-3/media/v10-deadline-final/deadline-context/ar-light-390-repeat-compact.png). Those are inspected existing visuals, not Stage 4 mockups. Carry over the coastline as context, disciplined bronze emphasis, opaque reading surfaces and qualifications near decisions. Do not recreate the Arrival globe or Concierge sheet on this editorial route.

Chapter navigation is a shortcut, not a required sequence. “Numbers”, “Place” and the primary action must remain reachable in at most two deliberate activations. Source details remain beside their fact, not solely at the bottom of the page.

## Responsive composition

- **1440:** 1280px content boundary, 12-column grid. After the cover, a seven-column sticky media rail and five-column narrative alternate their emphasis through Idea/Place/Residences. Numbers spans the full width. Reading text stays below 68ch. Media sticks below the header and releases before the next full-width section; it never traps wheel or keyboard scrolling.
- **1024:** five-column media/seven-column reading if text requires it; use a shorter sticky rail. Collapse chapter navigation into a labelled native disclosure before it overlaps titles or actions. No permanent third sidebar.
- **390 and 375:** one document scroll, 20px inline padding, full-width geography, then identity and evidence. Short project names may occupy two lines; long actual names wrap without ellipsis. Media is in normal flow, approximately 240–300px tall. A compact bottom action bar has one primary action plus More; it reserves its own page padding and yields to keyboard/dialogs. Sources are at least 13px; action targets at least 44px. At 500px viewport height, no root minimum height forces content below the viewport.
- **Arabic:** Amiri display, Plex Arabic UI, no italic. Use logical column/spacing rules; map coordinates and geographic bearing do not mirror. Native amount/currency, mixed-script project names and IDs use bidi isolation. Numeral preference applies to timeline, map annotations, year and source dates. Do not replace unknown source wording with an invented translation.

## Shared read contract needed

No TypeScript contract is declared here; Noir owns the approved shared schema. Proposed data requirements:

| Field group        | Required semantics                                                                                                                                                                                                                                                                        |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Identity           | Discriminator `REAL_REFERENCE_PROJECT`, `DEMO_PROJECT` or `DEMO_UNIT`; authorized entity reference; exact bilingual name; canonical server-generated href/slug; parent demo project identity only where valid. Noir proposes `project-`/`unit-` slug namespaces; parent approval pending. |
| Editorial evidence | Curated localized display facts referencing canonical `GroundedFact` and `GroundedSource`; original wording retained; record-level citation scope acknowledged. Unknown/unverified is a first-class state. No raw reference JSON dump.                                                    |
| Place/media        | Approximate center, named area, bounded authorized map projects, permitted POIs and source/licence attribution. Any future image needs rights, caption, alt text and whether it is generic/illustrative; no supplied project photography is assumed.                                      |
| Residences         | Reference categories with enquiry capability; demo project returns only authorized units, bounded and deterministically ordered. No private-derived total count/minimum or “sold out” inference.                                                                                          |
| Money/numbers      | Exact subject, native amount/currency/label, basis, date precision, optional static-FX conversions and rate date. Derived amount requires input fact IDs and units. Area benchmark/yield must state Demo or sourced basis. Missing values are not zero.                                   |
| Timeline           | Exact subject name/entity; supported milestones/timing/percentages; original wording; evidence mode and sources. Incomplete source schedules return a truthful unavailable state.                                                                                                         |
| Actions            | Server-derived capabilities and reasons: reference `ENQUIRE_PROJECT`, demo project `SELECT_UNIT`, unit `REQUEST_UNIT_VIEWING`; save target is real reference or demo unit only. Capabilities guide UI but never replace server authorization on actions.                                  |
| Context            | Brief/conversation reference within the current viewer's scope, return-to-map state and display preferences. URL carries public opaque identity only, not private facts or full sensitive Brief.                                                                                          |

Existing `getReferenceProject` is ID-only and always `ON_REQUEST`; a slug resolver and curated story DTO are needed. `getAtlasData` is a scoped summary, not the complete story source. Legacy `getProperty` already reauthorizes units, but the existing PropertyDetail mixes gallery, synthetic investment and unit actions; its presentation should not be reused wholesale for references. `ShortlistItem` and `ViewingRequest` are unit-only. The coordinated proposal preserves that and adds real-reference portfolio items separately; demo grouping records are not portfolio holdings.

## Financial and source decisions

ORLA illustrates a reference whose AED57.3m figure has an agent-listing basis, a four-bedroom label and month precision June 2026; it is not a live unit offer. SouthMED's EGP91.2m figure is a press-reported starting figure for a described villa category, with year precision 2026. Its public wording about a 1.5% down payment and plans up to 15 years does not establish a complete installment schedule. Never convert site/masterplan area into residence price per sqm. These examples derive from the supplied dataset and are not independently verified current offers.

UAE Golden Visa content is an indicative configured price-threshold comparison only, with date/basis and advisor confirmation; not residency eligibility advice. Do not place that treatment on Egyptian property or use an unknown/on-request amount as qualifying. Fictional unit rent/yield/community figures remain Demo estimates and must never be attached to reference projects as actual returns.

## Actual actions and recording plan

Primary recorded vertical slice uses a seeded, signed-in client and an authorized fictional residence: Concierge intent → map selection → story → select exact unit if needed → save to named portfolio → open bilingual source-bearing dossier → request viewing with Dubai/Cairo/London time-zone choice and explicit confirmation. Target budget: 30s context/map, 35s story, 25s save/portfolio, 25s dossier, 45s viewing, 20s margin. This is a test plan, not measured completion. Start the recording before the prompt; disclose seeded authentication and do not edit out waits.

Second branch uses a real reference: story → save reference → source-bearing dossier → residence enquiry, clearly not a booked viewing of an invented unit. Guest sign-in preserves the selected subject and draft; it does not auto-save or auto-submit after return. Private viewing remains a request pending confirmation, never a confirmed appointment unless supported by real workflow state. Sharing creates an explicit, revocable, viewer-authorized share artifact when available; do not label copying an access-controlled route “private sharing”.

## Proposed implementation ownership and gate

After contract approval, Story frontend may own new `src/components/story/*`, scoped stylesheet/copy and `app/[locale]/(public)/p/[slug]`. Noir owns story/read-model and workflow contracts; parent coordinates auth/actions/PDF/route integration. Existing LivingMap remains shared: proposed embedded layout behavior requires coordinated ownership, not an independent map fork. Legacy routes remain compatible until callers migrate deliberately.

First implementation slice: reference ORLA and SouthMED plus one authorized demo-project/unit pair, all eight chapters with honest unknown states, then actual workflow actions. Required review matrix is EN/AR × light/dark ×1440/1024/390, plus 375/short-height, no-JS identity/evidence, reduced motion, keyboard, all-rules axe, software fallback and real/tampered/revoked private entities. Record the full under-three-minute journey and preserve misses. Existing sub-two-second loading, physical-device/M1/native Arabic/full-AT limits carry forward; no design proposal closes them.
