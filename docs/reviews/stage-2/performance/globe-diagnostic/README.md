# Globe startup diagnostic

Production v3 Home still failed the performance gate (71, LCP 2.34s, TBT 1.73s), while Explore passed at 92. Two short CDP probes examined the existing production build on Apple M3 Metal, 390×844. A fresh browser is not proof that the OS/driver shader cache was cold.

The first probe sampled about 203.45ms in wrapped WebGL calls, including a 170.5ms synchronous `getProgramParameter(LINK_STATUS)` wait. The second shader-identification probe was warm: every recorded status wait was below 7ms. Its raw CPU profile and reduced call timings are preserved here. First-probe raw output was accidentally overwritten by the second probe; `first-probe-summary.json` retains exact tool-output values and clearly states this limitation. No cold/warm result is represented as a controlled benchmark.

Installed MapLibre 6.15 source corroborates the mechanism: `src/webgl/program.ts` synchronously queries link status before attribute/uniform setup. Globe fill/line subdivision primarily occurs in worker buckets; Chromium already defaults to one worker. The application repair therefore removes unnecessary opening shader variants: world cluster counts use native HTML Marker buttons backed by the same MapLibre cluster index, and the geographic land fill supplies its own outline instead of also drawing a separate coastline line. World markers hide behind the globe and support keyboard activation. Local Explore layers remain unchanged. No timer, user-agent/audit detection, dependency patch or manual shader prewarming was introduced.

The data-only cluster-index circle layer has zero fill/stroke opacity and zero stroke width. Installed `draw_circle.ts` returns before creating a shader in this condition, while retaining a queryable native cluster source. GPU cluster/count layers start at zoom 5 for this Arrival instance. The same clusters are therefore not duplicated as accessible controls. Actual transition and newly cold production measurements are required before claiming improvement.
