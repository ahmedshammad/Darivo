# Startup architecture follow-up

Read-only inspection found a bounded payload opportunity for hardening: move the legacy Shell and full next-intl message provider into a nested legacy route group while preserving the common locale root and persistent preferences. The current Shell calls translation hooks before returning no markup for Atlas; its imports still reach the route. The359-message catalog contributes about6KB gzip English/7KB Arabic, and the inspected intl chunk about12.1KB gzip. Preferences currently combines state/provider with translated controls, so those must be separated for a clean dependency boundary. The locale error UI also needs a small independent bilingual implementation or appropriate group placement.

Installed Next route-group documentation confirms nested groups retain URLs; a common root avoids full reloads associated with multiple root layouts. Any such change needs cold and client-side navigation tests across Atlas, login, profile, search and the guide, plus preferences/sign-out/error recovery. Arrival directly imports next-auth/react, so deferring only the legacy shell would not remove that dependency from Home.

This is not yet implemented or claimed as an LCP fix. Current hardware text paint is observed at50–51ms, while intl/layout requests complete later, around55–60ms. The136.9KB framework and47.6KB fonts complete before paint. Software observations instead delay text to1591–1664ms despite earlier resource arrival. The separate minimal software probe also shows a large plain-page startup delay. Measure trace/critical dependencies before attributing that delay or undertaking broad restructuring; preserve fonts, visible content and unchanged audit settings.
