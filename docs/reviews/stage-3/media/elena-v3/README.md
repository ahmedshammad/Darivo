# Elena preview and compact composer — development evidence

This is an implementation check, not a scored review or production performance result. The browser used the local development server with the explicit geographic fallback enabled. Each journey submitted the authored Elena prompt, awaited a completed response, and captured the geographic preview after the bundled coastline loaded.

The six screenshots cover English Noir at 1440×1000, Arabic Sand at 1024×1000, and Arabic Noir at 390×844. `checks.json` records three named place controls, an empty composer after successful submission, no page errors, no horizontal overflow, and no automated WCAG-tagged axe violations in each sampled state. The desktop reading viewport is 661 pixels tall after the empty composer contracts; the mobile reading viewport is 394 pixels tall. These are measurements of the captured layouts, not physical-device results.

Visual inspection confirmed that the preview preserves geographic orientation in Arabic, uses the actual bundled Natural Earth coastline, and identifies Palm Jumeirah, Dubai Hills and Downtown with matching numbered controls. It is explicitly a coarse regional preview: its coastline does not show Palm reclamation, roads, plot boundaries or school catchments. Each place button controls the one main map; the preview does not create another WebGL context. The main fallback no longer displays overlapping school names in these samples. Crowded labels yield while markers and their SVG titles remain.

The eight Concierge integration cases passed, including the preview's keyboard control, successful draft clearing, cancellation retention, editable Brief, two-market comparison, source disclosures, clear-history followed by a new signed-in request, and unsent Atlas entry in both languages. The migrated Atlas → Concierge → sign-in handoff passed separately after the login return-path allowlist was extended. Two additional Elena runs passed an assertion comparing actual POI text rectangles against one another and city labels.
