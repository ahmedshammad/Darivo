## Three problems

1. **A wrong island creates a wrong lead.** Replace broad keyword membership with canonical community matching and test the actual Sheikha result set. A correct quoted price does not make that location relevant.
2. **Teaching reads like repeated rejection.** Four notices precede Elena's mini-map according to the [manifest](../media/v2/manifest.json). Present one clear uncertainty statement with the useful neighborhood explanation. On [Arabic phone](../media/v2/elena-ar-light-390.png), the repeated opening fills the available reading area before the result.
3. **Phone control obstruction is real.** The manifest reports only 44×5.5px of the zoom-out target exposed. Reposition or appropriately hide controls when the sheet occupies that area; rerun the same expanded states.

I inspected desktop/tablet/phone in both languages and themes, plus timed stills from the six supplied recordings; I did not perform continuous playback, a native reader session or production signed-in handoff. The [validation checkpoint](../validation/README.md) reports 251 native tests, while the full local browser run retains a 66/67 result followed by a targeted repair pass. **Verdict:** The context and safeguards can support an advisor, but geographic accuracy and response hierarchy need repair before I would trust this to qualify a client unaided.
